# YGV608 as used by Namco ND-1 — rendering semantics

The executable form of this document is `tools/render_model.py`, which is
pixel-exact against MAME (`ref/mame/ygv608.cpp`) for every state in
`artifacts/states/` (`tools/regress_render.sh`, 65 states, 0 differing
pixels). Everything below is what that renderer does; write the RTL from
this and gate it against the renderer, one layer at a time (`--layer a|b|s`).

Scope: what MAME implements and ncv1 uses. Not covered: ROZ (ZRON), mosaic,
ROM DMA, raster IRQ position, border/blanking output. `m_dspe = 0` blanks
the planes and sprites (MAME then shows stale work-bitmap contents; treat
as "everything transparent, border colour").

## 1. Register-derived mode

| symbol | from | values seen |
|---|---|---|
| MD | R#7 bits 2:1 | 0 = 2 planes, 8-bit names; 1 = 2 planes, 16-bit names; 2 = 1 plane 16 colours; 3 = 1 plane 256 colours |
| bits16 | MD != 0 | 0 or 1: pattern name entries are 1 or 2 bytes |
| PGS | R#8 bit 0 | page shape when MD != 1: 0 = 64x32 tiles, 1 = 32x64 |
| page_x, page_y | MD, PGS | MD=1: 32x32; else PGS=0: 64x32, PGS=1: 32x64 |
| pny_shift | page_x | 5 if page_x == 32 else 6 |
| base_y_shift | page_y | 2 if page_y == 32 else 3 |
| PTS | R#9 bits 7:6 | 0 = 8x8 patterns, 1 = 16x16 (32x32/64x64 exist for sprites only) |
| SLH (h_div_size) | R#9 bits 5:3 | 0 = whole screen, 4 = 8-dot rows (galaga_arr) |
| SLV (v_div_size) | R#9 bits 2:0 | 0 = whole screen, 5 = 16-dot columns (menus, mappy) |
| col_shift | PTS, SLV | SLV==0: 8; PTS 8x8: SLV-4; PTS 16x16: SLV-5 (clamped to 8 if negative) |
| NA8 mask (na8_mask) | FLIP | FLIP=0: 0x0f, FLIP=1: 0x03 |
| FLIP | R#7 bit 6 | 0 in ncv1 |
| SPAS, SPA | R#10 bit 5, bits 7:6 | both seen |
| SPRD | R#10 bit 4 | sprite disable |
| PRM | R#11 bits 3:2 | 0 (sprites over A) and 1 (A over sprites) seen |
| CTPB, CTPA | R#11 bits 1, 0 | plane transparency enables |
| APF, BPF, SPF | R#12 bits 2:0, 5:3, 7:6 | colour fetch modes; APF=BPF=3 seen in galaga_orig |
| BDC | R#13 | border colour, 0xff on the title, 0 in games |
| gfxbank | cuskey +0C bits 1:0 | 0 so far |

Tilemap pixel size: `tw = page_x * pts`, `th = page_y * pts` (512x256,
256x512 or 512x512). Screen: 288 x 224, origin top-left of the raster
(MAME rotates it 90° clockwise for display: `png(x,y) = native(y, 223-x)`).

## 2. Pattern ROM addressing

The chip sees an 8 MB region; ncv1's 2 MB `nc1cg0.10c` is mirrored 4x
(address & 0x1fffff). Tile *code* to byte offset:

| gfx set | tile | bytes per tile | offset |
|---|---|---|---|
| 0 | 8x8 4bpp | 32 | code * 32 |
| 1 | 16x16 4bpp | 128 | code * 128 |
| 2 | 32x32 4bpp | 512 | code * 512 |
| 3 | 64x64 4bpp | 2048 | code * 2048 |
| 4 | 8x8 8bpp | 64 | code * 64 |
| 5 | 16x16 8bpp | 256 | code * 256 |

MAME bounds-checks `code >= region/bytes_per_tile` → code 0 (never hit
with a mirrored region, but the check happens *before* the gfxbank add).

**4bpp, 8x8 block:** 32 bytes, row `y` = bytes `4y..4y+3`, pixel `x` is the
nibble `x` of that row, high nibble first: pen = `byte[4y + x/2] >> 4` for
even x, `& 0xf` for odd x.

**4bpp larger tiles** are 8x8 blocks in Z-order (Morton) with the x block
index in the even bit positions:
`block = (bx&1) | (by&1)<<1 | (bx&2)<<1 | (by&2)<<2 | (bx&4)<<2 | (by&4)<<3`,
byte offset = `code*bytes + block*32 + (y&7)*4 + (x&7)/2`. So a 16x16 tile
is TL, TR, BL, BR at +0, +32, +64, +96; a 32x32 tile's four 16x16 quadrants
are at +0, +128, +256, +384; a 64x64's at +0, +512, +1024, +1536.

**8bpp:** one byte per pixel. 8x8: `code*64 + y*8 + x`. 16x16: four 8x8
blocks TL, TR, BL, BR at +0, +64, +128, +192 (`block = (y>>3)<<1 | (x>>3)`).

Pens: 4bpp pen 0..15, palette index = `colour*16 + pen`; 8bpp pen 0..255,
palette index = pen (colour is ignored: MAME's 8bpp gfx has one colour set).

## 3. Pattern name table (4096 bytes)

Cell `(col, row)` of plane P: `i = pn_base(P) + ((row << pny_shift) + col)
<< bits16`, with `pn_base(A) = 0`, `pn_base(B) = (page_y << pny_shift) <<
bits16` (B follows A; in MD=0 each plane is 2048 bytes, in MD=1 also 2048
bytes = 32x32x2; MD=2/3 use only A, 64x32x2 = 4096).

- byte 0: pattern name bits 7:0
- byte 1 (bits16 only): bits 3:0 → name bits 11:8, masked by NA8 mask
  (0x0f, or 0x03 when FLIP=1, when bits 3 and 2 become flip x / flip y);
  bits 7:4 → colour (4bpp only)
- code = name + `scroll_table[P][0xC0 + page] << (10 for 8x8, 8 for 16x16)`
  + `base_addr[P][row >> base_y_shift] << 8`, then the bounds check, then
  colour fetch (§5), then `+ gfxbank * (0x10000 8x8 4bpp / 0x8000 8x8 8bpp
  / 0x4000 16x16 4bpp / 0x2000 16x16 8bpp)`.
- base_addr: R#17–24, plane = reg >= 21; each register holds two 3-bit
  entries (bits 2:0 → entry 2k, bits 6:4 → entry 2k+1), 8 entries per plane
  indexed by `row >> base_y_shift`.

**Page** (5 bits, `& 0x1f`) — 0 whenever SLV != 0; otherwise from the
plane's whole-screen scroll `sx = st[0x80] | (st[0x81]&0x0f)<<8`,
`sy = st[tc] | (st[tc+1]&0x0f)<<8` where `tc = get_col_division(col)` (see
§4; 0 when SLV=0, which is the only case here):

| PTS | MD=1 | else PGS=1 | else PGS=0 |
|---|---|---|---|
| 8x8 | `((sx+col*8)%1024)/256 + (((sy+row*8)%2048)/256)*4` | `((sx+col*8)%2048)/512 + (((sy+row*8)%2048)/256)*4` | `((sx+col*8)%2048)/256 + (((sy+row*8)%2048)/512)*8` |
| 16x16 | `((sx+col*16)%2048)/512 + ((sy+row*16)/512)*4` | `(sx+col*16)/512 + ((sy+row*16)/1024)*8` | `(sx+col*16)/1024 + ((sy+row*16)/512)*4` |

(Integer division; note the 16x16 rows are not reduced modulo 2048 before
the divide — copy this literally.)

Cells with `col >= page_x` or `row >= page_y` are blank (code 0, colour 0);
plane B is blank in 1-plane modes.

## 4. Scroll tables (2 x 256 bytes; plane B = second 256)

| offset | meaning |
|---|---|
| 0x00 + 2k, +1 | y scroll of column group k (low byte, high byte). Whole 16 bits are used for the scroll (reduced mod `th`); only the low 12 bits for the page select. |
| 0x80 + 2k, +1 | x scroll of row group k, same rules (mod `tw`) |
| 0xC0 + page | high bits of the pattern name for that page |

`get_col_division(col)` = 0 if `(SLV & 4) == 0`, else
`((col >> col_shift) * 2) & 0x7f`. `get_row_division(row)` = 0 if SLH == 0,
else `(row & (page_y/2 - 1)) * 2` (rows 16–31 of a 32-row page reuse
entries 0–15: MAME's mask, keep it).

Scroll is applied the MAME tilemap way — the column/row groups are in
**tilemap** space, one tile wide/high:

- SLH == 0 (column scroll): `tx = (sx_screen + rowscroll[0]) mod tw`,
  `col = tx / pts`, `ty = (sy_screen + colscroll[col]) mod th`, where
  `colscroll[col]` is read at `get_col_division(col)` and `rowscroll[0]` at
  offset 0x80.
- SLH != 0 (row scroll): `ty = (sy_screen + colscroll[0]) mod th`,
  `row = ty / pts`, `tx = (sx_screen + rowscroll[row]) mod tw`, with
  `rowscroll[row]` at `0x80 + get_row_division(row)`. In this mode MAME's
  tilemap has a single column-scroll entry, so all columns use entry 0.

## 5. Colour fetch (R#12)

When a plane's fetch mode `cf != 0` (4bpp sets only), the colour comes from
the *code* instead of the name-table attribute: 8x8: `(code >> ((cf-1)*2))
& 0xf`; 16x16: `(code >> (cf*2)) & 0xf` (MAME's asymmetry; galaga_orig uses
cf=3 with 8x8 tiles, i.e. code bits 7:4). Sprites: `spf != 0` → colour =
`(code >> ((spf + [-1,0,1,2][size])*2)) & 0xf`.

## 6. Sprites (64 x 4 bytes, entry n at 4n)

| byte | bits |
|---|---|
| 0 | sy 7:0 |
| 1 | sx 7:0 |
| 2 | 7:4 colour, 3:2 "attr" (size or flip, see SPAS), 1 sx bit 8, 0 sy bit 8 |
| 3 | pattern name (8 bits) |

- `sy = ((sy9) + 1) & 0x1ff` — the +1 is real.
- SPAS = 0: size = SPA (R#10 bits 7:6), flipx = attr bit 3, flipy = attr bit 2.
  SPAS = 1: size = attr bits 3:2, flipx = SPA bit 1, flipy = SPA bit 0.
  Sizes: 0 = 8x8, 1 = 16x16, 2 = 32x32, 3 = 64x64 (gfx sets 0–3, always 4bpp).
- code = `((sprite_bank & mask[size]) << shift[size]) | name`, mask =
  {0xff, 0xfc, 0xf0, 0xc0}, shift = {8, 6, 4, 2}; bounds check; then
  `+ gfxbank * {0x10000, 0x4000, 0x1000, 0x400}`.
- Drawn in order entry 63, 62, … 0 (entry 0 ends up on top), pen 0
  transparent, clipped to the 288x224 screen. If `sx > 512-size` or
  `sy > 512-size` the sprite is also drawn at (sx-512, sy), (sx, sy-512),
  (sx-512, sy-512) (wraparound in a 512x512 space).

## 7. Compositing (MAME screen_update, modelled literally)

1. `bitmap = border colour` everywhere.
2. If 2-plane mode: plane B is drawn **opaque** (every pen) into a work
   bitmap; copied to the screen with pen 0 transparent if CTPB, else
   opaque. (Palette index 0 only, i.e. colour 0 / pen 0.)
3. If PRM is 1 or 3: sprites are drawn now (they end up under plane A).
4. Plane A is drawn into a zeroed work bitmap with **raw pen == BDC**
   (R#13) transparent — MAME's `set_transparent_pen(m_border_color)`
   compares the raw 4/8-bit pen, so BDC=0xff never matches 4bpp tiles and
   BDC=0 makes pen 0 of every colour bank transparent. Then copied to the
   screen with palette index 0 transparent if CTPA, else opaque (an
   undrawn pixel is copied as palette index 0 when opaque: the title screen
   shows palette entry 0 where tiles have pen 0xff... which never happens
   in 4bpp, so the effect is nil there).
5. If PRM is 0 or 2: sprites are drawn now (on top).

Palette: 256 x (R, G, B) bytes, 6 bits each: `out = (v & 0x3f) << 2 |
(v & 0x3f) >> 4`.

## 8. Per-frame fetch budget (from `--dump-fetches`, unique bytes)

Mappy gameplay: plane A 19 KB, plane B 1.6 KB, sprites 2.5 KB of unique
pattern bytes per frame; Galaga 8 KB. Per line the RTL needs at most
`(288/pts + 1)` tiles per plane (37 x 4 bytes for 8x8, 19 x 8 bytes for
16x16, one tile row each) and one row of every sprite overlapping the line
(size/2 bytes each, 64 sprites worst case).

## 9. RTL notes (`rtl/ygv608.sv`, `rtl/ygv608_render.sv`)

Gate: `tools/regress_video.sh` renders every corpus state through the RTL
(`sim/run_video.sh`, `sim/tb_video.cpp`) with the pattern ROM behind a
4–12 clock random-latency model and requires zero differing pixels against
`render_model.py`. 65/65 states pass; the worst line measured is 2611 of the
6210-clock budget (mappy 16x16 two-plane with sprites), the title screen
(8x8, one plane) about 1600.

- The state is loaded through the 68000 ports exactly as the game does
  (register select/data, P#0–P#3 with auto-increment), so the port logic is
  covered; port read-backs are implemented but not exercised by the bench.
- Line y is rendered during raster line 25+y into bank y&1 and scanned out
  on line 26+y; per line: border fill (skipped when plane B overwrites
  everything), plane B, sprites (PRM 1/3), plane A, sprites (PRM 0/2). One
  pixel written per clock; a 4bpp 8x8 tile costs one 32-bit fetch, 16x16 two,
  8bpp 8x8 two, 8bpp 16x16 four; a sprite row size/8 fetches.
- Raster: 414 x 258 at cen_pix, FV set at line 250 dot 0 (checked by the
  bench), FP at 26+vpos / 54+hpos*32 as MAME's screen coordinates.
- Block RAM: name table 2048x16 (byte lanes), sprites 64x32, scroll 512x8,
  palette 256x24, line buffer 1024x8: 52 Kbit; the four tables have a CPU
  read port and a renderer read port, so Quartus may duplicate them (up to
  ~96 Kbit, 10–11 M10K).
- P#7 bit 0 (HandleReset) clears the tables with a 2048-clock sweep instead
  of instantly; a CPU table write landing during the sweep wins that clock
  and the swept address is skipped. The game issues the reset once at boot,
  before it fills anything.
- Not implemented (assert `unsupported`): ROZ (ZRON), mosaic, ROM DMA, and
  a renderer line overrun. FLIP=1 name-table flips are implemented but the
  corpus never exercises them.
- No semantics in sections 1–8 had to change to reach zero differences.
